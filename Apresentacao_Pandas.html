a imagem que sustenta tudo
O DataFrame é uma
ficha de arquivo

Tem etiqueta (o índice), campos (as colunas) e um prontuário por pessoa (a linha).

  • Índice — o rótulo da linha. Não é a posição; é o nome.
  • Colunas — cada uma é uma Series, com seu próprio tipo.
  • Valores — a matriz de dados propriamente dita.
tudo que faremos hoje
montar a ficha → limpar a ficha → ler a ficha → grampear duas fichas diferentes.
01
Estrutura
o esqueleto

Antes de limpar ou cruzar qualquer coisa, é preciso saber onde o dado mora e como chamá-lo pelo nome. Seis tópicos, uma metáfora cada.

caixa 1 · o átomo
Series = valor + etiqueta

Uma mala sozinha não vai a lugar nenhum. É a etiqueta que diz de quem ela é. Na Series, cada valor carrega seu rótulo colado.

# duas portas, o mesmo resultado import pandas as pd s = pd.Series(data=[10,20,30], index=['a','b','c']) s = pd.Series({'a':10, 'b':20, 'c':30}) # dict já traz a etiqueta s['b'] → 20
a pergunta que fica
Se a lista comum já guarda valores em ordem, por que inventar a etiqueta? A resposta está no próximo slide.
caixa 1 · a superpotência escondida
Pandas soma pela etiqueta,
não pela posição

Duas Series de medalhas em ordens diferentes. O Python puro somaria errado. O Pandas alinha pelo índice antes de somar.

ser1 = pd.Series([1,2,3,4], ['EUA','Alemanha','Itália','Japão']) ser2 = pd.Series([4,3,2,1], ['Japão','Itália','Alemanha','EUA']) ser1 + ser2 → EUA 2 · Alemanha 4 · Itália 6 · Japão 8
o preço do superpoder
Etiqueta que existe só de um lado vira NaN. Isso é o mesmo mecanismo que vai explicar os joins na Caixa 4 — guarde a ideia.
caixa 1 · a molécula
DataFrame = Series
lado a lado

Várias Series que compartilham o mesmo índice. É por isso que a linha 3 de uma coluna corresponde à linha 3 de todas as outras.

  • df['Idade'] devolve uma Series — o tipo é o mesmo de antes.
  • df[['Nome','Idade']] devolve um DataFrame — lista dentro de colchete.
  • Cada coluna tem seu dtype. Uma coluna, um tipo. Sempre.
colchete simples × colchete duplo
Um erro clássico: df['A','B'] quebra. O certo é df[['A','B']] — a lista interna é a "sacola" das colunas pedidas.
caixa 1 · o nascimento
Duas portas, a mesma sala

Lista de listas: você digita linha por linha (como quem preenche fichas). Dicionário: você digita coluna por coluna (como quem monta a planilha).

porta A · por linha
base = [['João', 54, 'M'], ['Maria', 45, 'F'], ['Thiago', 15, 'M'], ['Sabrina',25, 'F']] df = pd.DataFrame(base, columns=['Nome','Idade','Sexo'])

mesmo df
porta B · por coluna
base = {'Nome': ['João','Maria', 'Thiago','Sabrina'], 'Idade': [54,45,15,25], 'Sexo': ['M','F','M','F']} df = pd.DataFrame(base)
regra prática
Dado que chega de formulário/input → porta A. Dado que chega de API/JSON → porta B. Dado que chega de arquivo → nenhuma das duas: pd.read_csv().
caixa 1 · o acesso
Nome na porta
× número do andar

loc chama pelo rótulo. iloc conta a posição, do zero. Quando o índice é 0,1,2… os dois parecem iguais — e é aí que a turma se perde.

df.loc['B'] # a linha etiquetada 'B' df.iloc[1] # a 2ª linha, seja qual for o rótulo df.loc['B', 'Idade'] # um valor único df.loc[['A','B'], ['X','Y']] # um retângulo
a pegadinha do fatiamento
df.loc['A':'C'] inclui C. df.iloc[0:3] exclui a posição 3. Rótulo é fechado; posição é meio-aberta.

caixa 1 · a peneira
Filtrar é deitar uma
peneira sobre a tabela

A comparação não devolve dados — devolve uma Series de True/False do mesmo tamanho. Só depois essa peneira é aplicada.

# passo 1 — a peneira (o que quase ninguém olha) df['Total'] > 2000 → True, False, False, True, ... # passo 2 — a peneira aplicada df[ df['Total'] > 2000 ] # colunas interligadas: filtro numa, resultado noutra df['Vendedor'][ df['Total'] > 2000 ]
por que isso importa
Entender que o filtro é uma Series intermediária destrava tudo depois: .sum() nela conta quantos passaram, e ela pode ser guardada em variável e reusada.

caixa 1 · criar e remover
axis=0 desce
axis=1 atravessa

O axis é o eixo ao longo do qual a operação caminha. Confundir isso é o erro nº 1 de quem começa.

# criar: aritmética entre colunas, vetorizada df['Comissao'] = df['Total'] * 0.05 # remover coluna → atravessa (axis=1) df.drop('Unnamed: 7', axis=1, inplace=True) # remover linha → desce (axis=0) df.drop(4, axis=0, inplace=True)
inplace=True: use com consciência
Ele altera o original e não devolve nada. df = df.drop(..., inplace=True) transforma seu df em None. Prefira reatribuir: df = df.drop(...).

caixa 2 · a régua de tolerância
thresh = quantos
precisam sobreviver

thresh=n significa: mantenha se tiver pelo menos n valores válidos. Não é "quantos NaN tolero" — é "quantos dados exijo".

df.dropna() # linha com QUALQUER NaN cai df.dropna(how='all') # só as 40 totalmente vazias df.dropna(axis=1, thresh=2) # coluna precisa de ≥2 válidos df.dropna(subset=['Total']) # só olha a coluna crítica
a ordem certa na base real
1º how='all' mata as 40 linhas vazias. 2º axis=1, how='all' mata as 3 fantasmas. Só então avalie o que realmente sobrou de nulo.

caixa 2 · o carimbo
apply: o carimbo
na esteira

Quando não existe método pronto, você escreve a regra uma vez e o Pandas a aplica em cada elemento, sem for.

# função nomeada — reutilizável, testável, com nome def faixa_etaria(idade): if idade < 18: return 'Menor' if idade < 60: return 'Adulto' return 'Idoso' df['Faixa'] = df['Idade'].apply(faixa_etaria) # lambda — para regras de uma linha só df['Comissao'] = df['Total'].apply(lambda x: x * 0.05)
quando NÃO usar apply
Se existe operação vetorizada, ela é ordens de grandeza mais rápida. df['Total']*0.05 ganha de apply(lambda...) sem esforço. apply é para o que não dá para vetorizar.

Média acima da mediana → cauda à direita (poucos muito altos). Quanto maior a distância, menos confiável a média como retrato do "típico". Renda, tempo de resposta e vendas quase sempre são assim.
caixa 3 · dispersão
std: o quanto
o dado estica

A variância soma os desvios ao quadrado — para que positivo e negativo não se cancelem. O desvio-padrão desfaz o quadrado e devolve a medida na unidade original.

  • Por que n−1? A amostra subestima a variação da população. Tirar um grau de liberdade corrige o viés.
  • Variância está em R$² — não tem interpretação prática. Use-a nas contas; reporte o desvio.

Total: std = R$ 664,69 em torno de R$ 1.708 → variação de ~39%. Uma carteira heterogênea.

caixa 3 · a régua de quatro marcas
Quartis, IQR e o
critério de outlier

Ordene os dados e corte em quatro partes iguais. O miolo — entre Q1 e Q3 — contém metade de tudo e é imune aos extremos.

# o cerco ao outlier, em 4 linhas Q1, Q3 = df['Total'].quantile([.25, .75]) IQR = Q3 - Q1 lim_inf, lim_sup = Q1 - 1.5*IQR, Q3 + 1.5*IQR df[(df['Total'] < lim_inf) | (df['Total'] > lim_sup)]
outlier ≠ erro
O critério só sinaliza. A venda de R$ 567 mil pode ser digitação errada — ou o melhor cliente do ano. Investigue antes de excluir.

caixa 3 · o motor da análise
Separar em gavetas ·
resumir · empilhar

Todo groupby faz três movimentos, sempre nesta ordem. Ver os três separados é o que destrava o conceito.

  • Split — quebra a tabela em pedaços, um por valor da chave.
  • Apply — roda a função dentro de cada pedaço, isoladamente.
  • Combine — empilha os resultados numa tabela nova, indexada pela chave.
# sozinho, groupby não devolve nada visível df.groupby('Vendedor') → <DataFrameGroupBy object> # ele espera o "apply" para agir df.groupby('Vendedor')['Total'].sum() → Caio 494.075,68

caixa 3 · relação entre variáveis
Andam juntos ×
o quanto andam juntos
  • Covariância só diz o sinal. Seu valor depende da unidade — R$ 445.144 não significa "muito".
  • Correlação é a covariância dividida pelos dois desvios — vira adimensional, entre −1 e 1. Comparável entre qualquer par.
na base de vendas
Preço × Total: r = 0,998 — quase perfeito, porque Total É calculado a partir do Preço. Quantidade × Total: r = 0,005 — nada. Correlação alta demais costuma ser redundância, não descoberta.

Juntar duas tabelas é fácil. Juntar sem perder linha e sem inventar linha é onde quase todo mundo erra — e o Pandas não avisa.

Empilhar caixas ×
costurar tecidos

caixa 4 · o conceito central
A chave é a
linha da costura

Duas peças de tecido só se unem onde os furos coincidem. A chave é o furo. Se ela não bate exatamente, a agulha passa direto — e o Pandas não reclama.

  • Mesmo nome nas duas → on='Produto'
  • Nomes diferentes → left_on='Produto', right_on='SKU'
  • Chave composta → on=['Loja','Data'] — quando uma coluna só não identifica
  • Tipos diferentes — '101' (str) nunca casa com 101 (int). Silenciosamente.
antes de todo merge, três perguntas
1. A chave é única na tabela da direita? 2. Os tipos batem? 3. O texto está padronizado nas duas?

caixa 4 · a raiz de quase todo erro
Cardinalidade:
1:1 · 1:N · N:N

A pergunta que decide tudo: a chave se repete? E em qual dos dois lados?

  • 1:1 — cada chave uma vez de cada lado. Resultado previsível.
  • 1:N — repete só à esquerda (o caso normal: muitas vendas, um produto). Seguro.
  • N:N — repete dos dois lados. O produto cartesiano explode a tabela. Quase sempre é bug.

3 vendas do Redmi × 2 linhas no catálogo = 6 linhas. Nenhuma delas errada individualmente; o total, completamente errado.

caixa 4 · o número que denuncia
835 entram. 1.130 saem.

Chave limpa, código correto, how='left' — que teoricamente "preserva a esquerda". E ainda assim a tabela cresceu 35%.

a regra que você deve sair sabendo
how controla quais chaves sobrevivem. A cardinalidade controla quantas linhas saem. São coisas independentes — e confundir as duas é o erro nº 1 em joins.
exercício · previsão de linhas
★ ★ ★ ☆ ☆caixa 4 · cardinalidade

A tem 5 linhas com a chave k = [1,1,2,3,3].
B tem 4 linhas com a chave k = [1,2,2,4].

Quantas linhas saem de A.merge(B, on='k', how='inner')? E no how='left'?
Faça no papel antes de rodar.

pressione R para revelar a resposta
resposta · inner = 4 · left = 6
Conte chave por chave, multiplicando as ocorrências:
k=1 → 2 × 1 = 2 · k=2 → 1 × 2 = 2 · k=3 → 2 × 0 = 0 · k=4 → 0 × 1 = 0
inner = 2 + 2 = 4 linhas. As duas linhas de k=3 desapareceram.

No left, k=3 não some — volta com colunas de B em NaN, ocupando suas 2 linhas: left = 4 + 2 = 6.

🎯 Note que A tinha 5 linhas e o inner devolveu 4, e o left devolveu 6. Nem "menos" nem "mais" é regra — só a soma dos produtos é.

caixa 4 · conferir a fatura
Todo merge merece
uma auditoria

Três linhas de código que transformam um join cego num join verificado. Faça delas um hábito.

# 1 — contar antes e depois (o mais simples e o mais eficaz) antes = len(vendas) r = vendas.merge(cat, on='Produto', how='left') assert len(r) == antes, f'explodiu: {antes} → {len(r)}' # 2 — indicator: de onde veio cada linha r = vendas.merge(cat, on='Produto', how='outer', indicator=True) r['_merge'].value_counts() → both / left_only / right_only # 3 — validate: o Pandas checa a cardinalidade por você vendas.merge(cat, on='Produto', how='left', validate='m:1') # MergeError se a direita tiver chave duplicada — ERRO em vez de silêncio
o presente que o validate te dá
Ele transforma um bug silencioso em exceção barulhenta. Um relatório que quebra é infinitamente melhor que um relatório errado que ninguém percebe.
